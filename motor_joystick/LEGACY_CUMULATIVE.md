# MaixCAM2 F32C 触屏摇杆与回零 demo

在 MaixVision 打开本目录 **`main.py`** 并运行。它是自包含单文件，只使用屏幕、触摸和电机 UART3，不需要 YOLO、相机采图、麦克风、外部 Python 包或其他 Python 文件。

## 接线

| MaixCAM2 | F32C 双轴总线 |
| --- | --- |
| B2 / UART3_TX | RX |
| B3 / UART3_RX | TX |
| GND | GND / 电机电源负极 |

默认 `/dev/ttyS3`、115200、8N1，底部 yaw 为 ID 1，上部 pitch 为 ID 2，两电机在同一总线。电机使用独立 8～15 V 电源，推荐约 12 V；相机使用原有独立供电，电机电源不能接到相机 IO。只保留本 demo 一个 UART 主控，不同时运行电脑 USB-TTL 控制器或声音跟踪程序。按实物接口一的 RX/TX/GND 标签接线，不凭线色猜针序；四芯直通接口本身不是电机控制口。

## 第一次运行

1. 断电接线并核实电机 ID，支撑或平衡俯仰负载。机械原点必须已用 v3 标定：Y 的真实垂直姿态是 0°，X 的零向也必须正确。**此 demo 不标定新的机械零点，也不写 Flash。**
2. 运行 `main.py`。程序先请求双轴失能，再读取累计与机械角度并建立固定参考；画面出现 `DISABLED`、`REF VALID` 后才可操作。无法取得双轴反馈或位置超界时不使能。
3. 对照实物姿态检查屏幕 MECH/相对角度。确认已保存的零点正确后点 **ZERO OK**。这个按钮只是本次会话的人为确认，不会把当前姿态设为零；不要在零位尚未标定时用它代替标定。
4. 点 **ARM**：先读双轴当前位置、预装当前保持目标，再请求使能。此处无使能状态回读，屏幕 ARMED 表示请求流程完成。
5. 按住左侧圆形摇杆控制：左右为 yaw，上下为 pitch；偏移越大，目标变化越快。松手以当时测得的位置作为保持目标。单次按住超过 8 秒停止推进，需要抬手再按。首次只做很小位移检查实际方向。
6. **DISARM** 随时请求双轴失能、取消回零。失能可能使 Y 因重力下落，应支撑负载。
7. 需要回零和清累计时，在 ARM 状态点 **HOME+CLR**，并确保俯仰负载在后续失能阶段仍能保持零位。全过程可用 DISARM 取消。

屏幕以 640×480 逻辑坐标绘制，适配相同长宽比的设备显示/触摸；当前 MaixCAM2 默认屏幕为 640×480，其他旋转/裁切显示模式须重新核对触摸对应。

## HOME+CLR 的实际顺序

1. 使用已保存的机械零点，把 `M` 换算为带符号机械位置，建立 `Z=T-M_signed`。用多圈位置命令返回逻辑 yaw=0、pitch=0；不使用可能绕过背面禁区的单圈最短路径。
2. 以低速回零，默认目标速率 yaw 6°/s、pitch 5°/s；检查新鲜累计/机械反馈、参考一致性、位置限位、反向/无进展迹象和界面心跳。默认最长 45 秒。
3. 双轴累计映射与机械角度都在 ±0.5°内、速度回读为零且稳定至少 0.6 秒后，请求双轴失能。再检查三组静止反馈，累计变化不超过 0.2°。失能后离开零位就中止清零。
4. **只有上述验证通过**，才向每个电机发送 `0x09` 清本次上电的累计角度，每轴分别读回累计角度要求在 ±0.2°内，并检查机械角度仍在零位范围。第一轴读回失败，不继续清第二轴。
5. 用新累计值重新建立机械参考，清掉旧的连续性历史和目标。成功显示 **HOME_DONE_DISABLED**，保持失能；再次运动必须重新点 ARM。

`0x09` 清的是会话累计寄存器，**不改变已保存的机械零点**。主流程不发送 `0x0A` 重新设机械零点，不发送 `0x08` 保存参数。HOME+CLR 不是碰限位开关寻找未知原点，也无法修复错误的机械零位标定。

## 保护与已知限制

- yaw 默认 -150°～+150°，pitch 固定不超过 -100°～+100°。只在该唯一单圈范围内运行，不演示无限旋转。角度回读分辨率为 0.1°；计算只消除浮点尾差，不扩大实际限位。
- 单一后台线程拥有 UART，UI 只更新有界摇杆/请求邮箱。ARM/位置命令发送前仍检查新鲜零点、有效 ARM 请求和界面心跳；主循环不刷新心跳超过 0.8 秒会锁定故障并尝试双轴失能。
- 回零时摇杆输入不参与目标；清零期间拒绝 ARM，完成后不自动重新使能。清零中断或一轴清零失败使参考失效，停止运动并要求重启检查。
- 反馈丢失、非预期累计跳变、机械/累计不一致、超界、回零超时等会锁定故障。故障后可继续读取诊断，但不自动恢复或重建零点，需停止 demo、排查、重启。
- 原协议没有使能/失能状态 ACK。串口失联时，失能命令也可能无法送达；软件不是独立急停或电源切断。位置进展检查也不是力矩/电流测量。首轮实物测试应空载或可靠支撑，准备独立切电手段。
- 单圈角度不能恢复断电前历史圈数，也不能检测所有特殊位置的整圈累计重置。电机独立重启后，应停止并重新运行 demo。

## 配置和维护

仅部署 `main.py` 时可直接修改其顶部 `CONFIG`：`motor_ids`、`motor_signs`、`limits` 等。改方向用相应 `motor_signs` 的 ±1，不要交换 TX/RX 来改方向。设置 `mechanical_zero_confirmed=True` 会跳过每次 ZERO OK 确认，仅限已核对实物标定的设备；默认 False。

维护版在 `src/`，协议和安全串口基类在 `vendor/`。修改后在电脑重新生成：

```powershell
python -B MaixCam/apps/motor_joystick/build.py
python -B -m unittest discover -s MaixCam/apps/motor_joystick/tests -v
```

`build.py` 只生成文件，不连接设备。协议和基类复用本地 `sound_yolo_gimbal/vendor/protocol.py` 与 `src/motor.py` 快照；基类只增加角度计算的浮点尾差归一化，避免 +100°被表示为 100.00000000000001 而误触发越界。机械协议依据当前 `gimbal-zero-worktree` v3 文档（已复核提交 `2a55978`）与本地 F32C 厂商手册。`source_hashes.json` 记录生成入口的实际来源哈希。
