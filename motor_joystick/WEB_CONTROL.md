# 用电脑控制 F32C 云台（MaixCAM2 中转）

运行入口是 **本目录 `main_web.py`**，在相机的 MaixVision 中运行。电脑只需要浏览器，无需安装 Python 或连接 USB 转串口。文件内已包含网页及串口驱动，单独传这一个文件即可。网页没有视频预览。

2026-10-30 最新安装配置：相机倒装，**左右输入反向，俯仰限位 −100°～+30°**。机械坐标、垂直零位和 HOME 不变；上下输入方向沿用原设置。两个单文件入口共享这份配置，修改单文件后重启应用才能生效。

用户反馈上一版测试无明显问题后，本次提高目标速度上限：手动 YAW **12→24°/s**、PITCH **8→16°/s**；HOME **6/5→10/8°/s**。这是程序目标上限，不代表实物测得速度翻倍；实际速度取决于加减速、反馈和负载。网页会显示当前加载的速率。

最新行为：**HOME 到位后保持使能，显示 HOME_HOLD；新增“重新检查状态”，手动调整或排除故障后不必重启脚本。** 首次使用新功能需替换并运行新版、刷新网页。

## 接线和启动

保留现有接线：MaixCAM2 B2/UART3_TX → 电机 RX；B3/UART3_RX ← 电机 TX；GND 共地。电机独立供电，ID 默认 yaw=1、pitch=2，115200 baud。

1. 在 MaixVision 停止旧摇杆／跟踪程序，避免两个程序争用 UART3。
2. 在 MaixVision 打开 **`main_web.py`** 并运行。默认先请求双轴失能并读取机械角度。
3. 查看控制台 `COMPUTER OPEN: http://...:8080`，在电脑浏览器打开其中与电脑互通的相机地址。也可以使用 MaixVision 连接的相机 IP：例如设备 IP 为 `192.168.100.210` 时，访问 `http://192.168.100.210:8080`。这个 IP 仅为示例，以当前连接为准。
4. 电脑和相机须通过 Wi-Fi、网线或已建立的 USB 网络互通。仅有无法互通的 USB 连接不能使用本网页。不要将相机的 IP 换成电脑的 localhost，也不要双击 Python 文件当网页打开。
5. 待网页显示 `DISABLED`、有效机械反馈后，点 **连接控制**。确认已保存的机械零点与真实姿态一致，特别是 pitch 垂直方向为 0°，再点 **ZERO OK → 手动使能 / ARM**。连接与 ZERO OK 都不会自动使能。
6. 按住拖动摇杆，或者按键盘方向键。左右控制 yaw，上下控制 pitch，松开保持当前实测位置。倒装适配使用 `joystick_signs=(-1,1)`，同时作用于网页、方向键和触屏；输入反向无需修改反馈坐标的 `motor_signs`。
7. **HOME** 回机械原点，确认到位、静止后保持使能，显示 **HOME_HOLD**。可直接继续摇杆控制，或再次 HOME。保持期间需让网页持续连接；关页、切后台、失焦、断连及故障仍会请求失能。
8. **DISARM** 或空格发出失能请求，并断开当前控制会话。需要手动调整时先 DISARM、支撑负载再调整。
9. 调整后点 **重新检查状态**，通过后显示 `DISABLED`。再点 **连接控制 → ZERO OK → 手动使能**，无需重启脚本。

屏幕控制版 `main.py` 和电脑控制版 `main_web.py` 每次只运行一个。`ZERO OK` 只确认现有机械零点，不会把当前位置标定为新零点。

## 启动即 FAULT：PITCH 越界

用户回传的板上日志为 `Mechanical position outside calibrated limits`，诊断机械角度 yaw=7.7°、pitch=116.2°。pitch 超出 ±100°，程序在使能前已拒绝运动。这与累计角度无关，未使能时也能读取机械角度。日志列出多个本机接口 IP，不表示电脑能通过所有这些地址连接。

当时用户选择保留限位；随后针对倒装将允许范围进一步收紧至 **−100°～+30°**。支撑俯仰负载，在确认失能的情况下将其移回当前允许范围，最好靠近已经标定的机械零位，然后点 **重新检查状态**。故障不会自行解除或使能；检查通过后再连接控制、ZERO OK、手动使能。如果实际已在预期零位而反馈仍是 116.2°，应核对机械零点标定及轴 ID，不能把 ZERO OK 当作校准键。

修订后，报错包含轴名、ID、实测角度与限位。网页分别展示有效控制角度和诊断机械反馈及每轴反馈年龄：尚无有效控制反馈时显示 `--`，不再将初始 0°显示为真实姿态，控制反馈年龄也不再显示成开机经过时间。诊断更新不会恢复控制参考，或刷新控制反馈的时间戳。手动使能按钮旁显示不能使能的原因。

## 控制行为

### `Axis moving after disable` 是什么

这是之前版本 HOME 到位、请求双轴失能后的静止验证报错：其中一轴的转速反馈不为零。可能是惯性、重力移动或反馈滞后，单凭截图不能区分。当前按用户要求，正常 HOME 结束后保持使能，不再主动失能并执行这段检查。回零前的零速度与稳定检查仍保留。速度类型 0 按整数 RPM 解码，角度类型仍按 0.1°解码。

仍有故障时，程序保持故障锁定并继续尝试失能，不自动重新使能。支撑并检查负载、平衡和零位，静止后点 **重新检查状态**。保留首次 `MOTOR_FAULT` 及前后状态便于排查；速度检查不是电气失能状态的 ACK。

### 重新检查状态的流程

- 仅在失能或 FAULT 时接受，正在运动、HOME 或保持使能时需先 DISARM；重复提交检查会被拒绝。
- 按钮只向现有串口线程提交请求，同一线程请求双轴失能，读取三组新机械角度和零速度，并检查当前限位和静止变化 ≤0.2°；检查期间只发送失能与查询指令。
- 通过后才清除故障、回到 DISABLED，更新为当前实测姿态；取消旧网页控制令牌、旧目标与 ZERO OK 确认，不自动使能。
- 检查失败时显示本次原因（仍超限、在运动、反馈缺失、失能请求失败等）。排查后可再次按按钮；DISARM 可取消检查。
- 不标定机械零点、不清累计角度、不发送保存参数。脚本保持运行；初次打开 UART 失败也允许主动重新尝试。

### 2026-10-30：失能时手动移动与跳变保护

旧版在失能时仍按电机设定转速检查相邻角度变化，手动调整轴姿态较快也可能触发 `Unexpected mechanical angle jump on axis 1`；`axis 1` 是数组第二轴，即默认 ID=2 的 pitch。截图只说明该检查触发，不能据此确定真实移动、反馈异常或机械下落中的哪一种原因。

修订版在没有使能、也没有待处理 ARM 请求时，允许范围内的手动调整，并更新当前实测位置；绝对限位仍一直检查，pitch 超出 −100°～+30°仍锁定故障。ARM 准备及使能运行期间保留相同的跳变阈值。手动调整完成后，支撑并静止轴姿态，再进行 ZERO OK 和手动使能；使能时重新读取并预装当前位置。

再次触发跳变时，故障文字包含轴名、ID、前后角度、变化量、时间间隔、允许变化量及使能状态。日志中的 `last_angle_jump` 保存跳变证据，后续诊断读取不会覆盖；成功主动重新检查后清除。故障不会自动解除或使能。

- 仍为机械角度模式：默认单圈直通模式 4、位置指令 `0x03`、机械角度反馈类型 2；不读取、检查或清除累计角度。HOME 只返回机械原点。
- 默认 yaw 限位 ±150°、pitch −100°～+30°，手动最高 24°/s、16°/s，回零 10°/s、8°/s。继承小步目标、反馈超时、角度跳变和运动异常保护。
- 一次连续非零摇杆／方向键输入最多 8 秒；上限由相机检查，到时保持位置，需要松开后再次输入。
- 网页约每 80 毫秒在上一次请求完成后发送下一次控制。相机收到的有效控制输入超过 **0.6 秒**未更新时，撤销会话并请求双轴失能；电机线程另有 **0.8 秒**心跳保护。实际失能时间还受线程调度、串口反馈等待影响，这不是硬实时切电。
- 关闭页面、切后台、窗口失焦会尝试发送失能请求；若请求未送达，由超时保护处理。回零过程中也必须保持网页连接。恢复网络不会自动使能。
- 同一时间只允许一个控制会话。其他网页可查看状态，但不能接管；刷新页面后旧会话最多等待 0.6 秒过期，再连接。
- 使用同源 JSON 请求、会话令牌和递增序号拒绝跨站及过期／重复指令。服务供可信局域网测试使用，没有账户认证和 HTTPS，不要做公网端口映射。

软件失能不是电源切断，断线时失能请求可能无法到达驱动板。俯仰轴失能可能受重力下落，首次测试应支撑负载。发生硬件故障后保留完整日志，排查后可主动重新检查。

## 修改配置与验证

为减少软件指令引起的抖动，当前默认 `position_mode=4`（厂家单圈直通模式），由程序限制目标加减速，避免连续重发 T 型规划目标。没有实机证据证明旧模式是实际抖动的唯一原因，直通模式和负载响应仍需上板核对。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `joystick_signs` | `(-1,1)` | 只反转左右输入，反馈与零位不变 |
| `limits` | `((-150,150),(-100,30))` | yaw / pitch 机械坐标限位 |
| `max_rate` | `(24,16)` | 手动目标速度上限，单位 °/s |
| `home_rate` | `(10,8)` | HOME 目标速度上限，单位 °/s |
| `command_accel_deg_s2` | `(80,60)` | 软件目标速度平滑变化上限，单位 °/s² |
| `position_period_s` | `0.04` | 每轴正常位置指令最多约 25Hz |
| `manual_lead_deg` | `3.0` | 目标距离最近实测角度上限，旧版为 1.5° |
| `motor_rpm` | `5` | 发送给驱动的速度限制，旧版为 3 RPM |
| `motor_acceleration` | `10` | 配置给驱动的加速度参数；直通模式是否使用由固件决定 |

程序使用浮点目标逐步推进，编码为 0.1° 单位后目标未变化就不重复发送；只活动的轴发新位置。松手会优先锁定一次实测保持位置，随后不追随每次反馈的细微波动。这次保持更新可绕过普通位置限频，DISARM 也不会等待平滑过程。目标离最近实测位置不超过约 3°，发送前仍检查参考、心跳与限位。提高前导量是为了减少高速下等待反馈造成的限速，也增加了尚未执行完的目标角度上限。软件目标的加速度限制不是实测电机加速度；反馈读取和保护不做平滑。

单文件运行时直接修改 `main_web.py` 顶部的 `CONFIG`；HTTP 地址／端口在文件内搜索 `WEB_CONFIG`，默认端口 8080。如端口被占用，应停止占用程序或更换端口。服务绑定失败不会启动电机线程。

维护源码时修改 `src/web.py` 和共享驱动源码，然后生成并检查：

```powershell
python -B MaixCam/apps/motor_joystick/build_web.py
python -B -m unittest discover -s MaixCam/apps/motor_joystick/tests -v
node MaixCam/apps/motor_joystick/tests/test_web_client.cjs
```
