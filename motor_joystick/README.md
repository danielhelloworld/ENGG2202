# MaixCAM2 F32C 摇杆：仅机械角度测试版

**电脑控制版：在相机上运行 [`main_web.py`](main_web.py)，电脑浏览器打开相机 IP 的 8080 端口。支持网页摇杆、方向键、HOME 和 DISARM，接线沿用 UART3 B2/B3。完整步骤见 [WEB_CONTROL.md](WEB_CONTROL.md)。**

2026-10-30 修订：适配相机倒装，左右输入反向，pitch 限位为 **−100°～+30°**；手动目标速度上限 **24°/s、16°/s**，HOME 为 **10°/s、8°/s**。新增 **RECHECK STATUS / 重新检查状态**，失能时可解除已排除的故障，无需重启脚本；HOME 到位后进入 **HOME_HOLD**，保持使能。当前整套 81 项电脑测试通过，新功能仍待实机确认。

2026-10-21 根据实板截图改为 **MECH ONLY**。在 MaixVision 停止旧程序，重新打开本目录 **`main.py`** 并运行即可。单文件包含运行所需代码，不需要其他 Python 文件、模型或麦克风。

## 为什么旧版显示 FAULT

截图底部是 `ZERO_REFERENCE_LOST: Mechanical/total reference mismatch`，表示旧程序检测到保存的累计/机械映射与新反馈不一致，于是锁定故障并请求双轴失能。`FEEDBACK AGE 16.13s` 是最后一组有效控制反馈的年龄，不意味着串口完全没有数据。故障后 RAW/MECH 仍可被诊断读取更新，而上方 YAW/PITCH 保留最后有效控制角度，不能只用这一帧画面复原触发瞬间。

仅凭截图不能确定是电机重启/累计寄存器变化、顺序采样差异或异常反馈，也没有证据说明电机损坏。本版先隔离累计角度依赖进行测试；若机械角度本身跳变、越界或断流，仍会停止。

## 当前明确改变

- 只查询机械角度（反馈类型 2），到位时可查询速度（类型 0）。不查询累计角度（类型 1），屏幕显示 `TOTAL UNUSED -- / --`。
- 默认使用单圈直通模式 4、`0x03` 位置指令；程序平滑生成局部目标，不发送多圈位置 `0x02`。
- 不做机械/累计一致性比对，不计算累计零点映射。不发送 `0x09` 清累计、`0x0A` 改机械零点或 `0x08` 保存参数。
- **HOME**：仅返回已保存的机械原点，确认到位、静止后保持使能，显示 `HOME_HOLD`。不清累计角度。
- 摇杆松手保持当前实测位置；默认单次按住最多 8 秒，需要抬手再按。

## 接线与操作

| MaixCAM2 | F32C 总线 |
| --- | --- |
| B2 / UART3_TX | RX |
| B3 / UART3_RX | TX |
| GND | GND / 电机电源负极 |

默认 UART3 `/dev/ttyS3`、115200 8N1，yaw ID=1，pitch ID=2。电机独立 8～15 V 供电，推荐约 12 V，相机使用原有独立供电。只保留本 demo 一个总线主控；不要同时运行旧 demo、电脑上位机或声音跟踪程序。

1. 停止旧版程序并完成接线。不要边运行旧串口线程边启动新版。电机接线仍应断电操作。
2. 运行新的 `main.py`，屏幕标题应显示 **F32C JOYSTICK | MECH ONLY**，日志包含 `MECHANICAL ONLY: mode=4 position=0x03 feedback=2`。
3. 默认先请求失能并读取机械角度。确认 `DISABLED`、`REF VALID` 且 MECH 与真实姿态相符。
4. 已保存的机械零点必须正确，特别是 Y 的真实垂直方向为 0°。确认后点 **ZERO OK**，再点 **ARM**；ZERO OK 只是人为确认，不标定新零点。
5. 先轻推摇杆测试几度，确认实际 yaw/pitch 方向。左右控制 yaw、上下控制 pitch，松手保持。当前 `joystick_signs=(-1,1)` 只反转左右输入，机械坐标和 HOME 零位不变；若调整输入方向，停止程序后修改 `joystick_signs`，不要用 `motor_signs` 代替安装方向设置。
6. 点 **HOME** 回到机械 0°；回零时屏蔽摇杆，过程可用 **DISARM** 中止。完成后保持使能，可继续摇杆控制，或再次 HOME。网页断连／心跳超时和故障仍会失能。
7. 手动调整或故障排除后，确保已失能，点屏幕 **RECHECK STATUS** 或网页 **重新检查状态**。检查通过回到 `DISABLED`，再 ZERO OK → ARM；仍有问题则保留故障并显示原因。失能时 Y 可能受重力影响，请支撑负载。

## 单圈路径保护

单圈指令可能走最短路径，因此本版不直接下发相距很远的机械目标。每一小步按设定速率推进，并限制目标离最近实测角度默认最多 3°（另留 0.05°协议量化余量）；发送前再次验证端点均在允许范围内。为适应提速，前导量从 1.5°增加到 3°，提高了每次尚未执行完的目标角度上限。

yaw 默认 -150°～+150°，pitch 默认 **-100°～+30°**，两轴均不跨 ±180°。回零时逐步逼近 0°，不直接发送远距离单圈目标。使能时实际反馈异常跳变仍会中止。

平滑策略见 [电脑控制说明](WEB_CONTROL.md)：软件限制目标速度变化，默认每 40ms 最多发送一组位置，去掉协议量化后相同的目标。松手优先发送一次实测保持位置，随后固定目标，不追逐反馈噪声。控制反馈、限位与失能检查仍在更快的串口工作循环中执行。

默认摇杆目标速率 yaw 24°/s、pitch 16°/s，HOME 为 10°/s、8°/s；发送给驱动的速度上限为 5 RPM。实际运动速度仍受加减速、反馈、目标前导量和负载影响。HOME 超时 45 秒，要求机械角度在 ±0.5°、速度为零并连续稳定至少 0.6 秒。完成后保持使能，以机械 0°为固定目标。旧版 HOME 后的失能检查不再是当前流程。

## 仍保留的保护与边界

机械反馈过期、丢失、跳变、实测越界、UI 心跳超过 0.8 秒、运动方向/进展异常、回零超时等仍会锁定故障并尝试双轴失能，不自动重新使能。故障排除后可主动 RECHECK；被动诊断读取不会恢复控制资格。检查通过后仍需 ZERO OK 和手动 ARM。

本次去掉累计角度校验，也失去了通过它发现某些电机重启/坐标变化的交叉检查；不能把本版说成全面修复原故障。机械零点偏移参数本身没有公开回读，错误标定也不会被 ZERO OK 自动纠正。

软件失能不是切断电源，失联时失能命令也可能无法送达；位置检查不是力矩/碰撞测量。首次测试请空载或可靠支撑，准备独立切电手段。

## 配置、维护及验证

单文件部署可直接修改 `main.py` 顶部 `CONFIG`。当前入口固定使用 `mechanical_only`，不要改回旧 `mechanical` 名称。维护源在 `src/`，修改源后重新生成：

```powershell
python -B MaixCam/apps/motor_joystick/build.py
python -B -m unittest discover -s MaixCam/apps/motor_joystick/tests -v
```

`src/mechanical_only.py` 是当前驱动。旧 `src/service.py` 和 `vendor/motor_base.py` 保留用于通用串口/安全逻辑复用及旧流程回归测试，旧流程说明在 `LEGACY_CUMULATIVE.md`，当前入口不会执行旧累计清零流程。单圈模式与帧编码依据本地最新 v3 的 `MODE_SINGLE_DIRECT=4` 和 `single_turn_position_frame()`（`0x03 + uint16 0.1°`）。

81 项电脑端测试通过，覆盖重新检查事务、失败原因、取消检查、旧控制令牌失效、同一串口线程从故障恢复、HOME 保持使能及保持期间的心跳保护。原有倒装、提速、平滑、限位、回零、异常失能和禁止累计／标定指令等回归继续通过。

这些是协议与位置模型测试。用户截图证明旧版已显示实物反馈并触发保护，但不能证明新版已在电机执行成功。新版单圈固件行为、真实运动方向、屏幕触摸和负载稳定性仍待实机验证。若仍报错，请保留从启动起的完整控制台日志，尤其是首次 `MOTOR_FAULT` 及此前几条状态。
