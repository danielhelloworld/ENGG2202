# MaixCAM2 YOLO 点选跟踪（无声音模块）

2026-10-30。MaixVision 打开本目录 **`main.py`** 运行，电脑浏览器访问 **`http://相机IP:8080`**。单文件已包含网页、YOLO/ByteTrack 接口和最新机械角度电机控制，不需要上传旁边的 Python 文件；模型仍需在相机上存在。

本次修订 **`manual-half-soft-v6`**：用户反馈摇杆过快、快速加速时触发 FAULT／失能，因此将 v5 摇杆速度减半至 **240/180°/s**（yaw/pitch），手动加速度上限减半至 **900/750°/s²**、变化率降到四分之一。修正已发合法位置目标与机械反馈采样错位时可能误报角度跳变的问题，并避免小幅反馈回摆导致同向目标回撤、手动阻尼补偿反向推动。跟踪仍为 **150/120°/s**、HOME **108/90°/s**，卡阻观察仍为 **1.8 秒**，保留原限位及查询失败保护。相机 HTTP 读取超时，具体实机 FAULT 原文尚未取得；本次修复依据代码与离线复现，仍需实机核对。

## 当前功能

- 启动后先确认相机、YOLO 和机械反馈有效，再自动初始化回机械原点；检测显示所有模型类别，不自动选目标。**运行脚本会自动使能并回零**，先确认路径畅通。
- 预位自动回零完成后，可用网页摇杆、方向键或相机屏幕右下摇杆调整位置。手动推摇杆会取消已选目标，松开保持位置。
- 手动 ARM 只使能保持，不触发 HOME。当前位置即使在正常限位外也可 ARM，摇杆仅允许小步向正常范围内调整，向外推则保持；松开保持调整后的新姿态，进入正常范围后才允许跟踪。HOME 与 ARM 完全分开，失能时点 HOME 不会自动使能。
- 在相机屏幕或网页图像里点击检测框，锁定对应 `(类别 ID, 跟踪 ID)`。多个框重叠时优先选择较小框。两个界面共用目标状态。
- 保留 1101 `mainweb.py` 的多类别 YOLO + ByteTrack、同 ID 锁定、中心死区、EMA 和单步限幅思路。没有外观重识别或跨 ID 自动换人功能。
- 同 ID 连续有效观测后，使用机械反馈补偿相机自身转动，估计目标的短时图像运动并稍微提前纠偏。短暂丢失最多低速预测移动 **0.15 秒**，随后保持等待相同类别、相同跟踪 ID 恢复；超过 **2 秒**未恢复则释放目标并自动回机械原点。2 秒计时仍从最后一次真实检测开始，沿用 1101 的 `gimbal.reset()` 行为。
- **第一次按 C：清除目标并保持当前位置；第二次按 C：回机械原点。** 屏幕 `C: CLEAR / C: HOME` 和网页按钮执行相同操作。网页键盘 C 忽略长按重复；重新选目标或手动移动会重新开始这两步操作。
- HOME 到位后保持使能，显示 `HOME_HOLD`；可继续操作。网页失焦／切后台／离开页面／心跳超时均交回相机继续运行，手动输入松开。视觉短时延迟先保持，持续无有效画面再失能。
- 保留 **重新检查状态**，失能后调整或排除故障，无需重启脚本；默认仍认可已保存的机械零点，检查通过后手动 ARM，再按需 HOME，不会自动反复使能。

原版 1101 按一次 C 会直接清除并回中位；本程序按本次要求拆成两次。丢失 2 秒回原点仍沿用原版。没有声音触发、自动搜索和自动选中目标。

## 在 MaixVision 运行

1. 停止其他占用相机、显示或 UART3 的程序。打开本目录 **`main.py`**。
2. 核对文件内 `CONFIG` 的模型路径。默认 `model_kind="YOLO11"`、`model_path="/root/models/yolo11n.mud"`，所引用的 `.axmodel` 也必须存在。已有 YOLOv8 的 MaixCAM2 模型时，可对应改成 `YOLOv8` 和其 `.mud` 路径；不能直接用 1101 的 `.pt` 文件。
3. 确认回零路径畅通，再运行。程序先确认相机、推理和有效机械反馈，随后自动请求使能并回到保存的机械 `(0°,0°)`。例如 pitch=116.2° 或 −120°不会再因超出正常工作限位而拒绝初始化。起始位置不受工作限位限制，但无反馈、非法反馈或明显运动异常仍会阻止启动。
4. 初始化回零阶段屏蔽手动移动和点框，到位后显示 HOME_HOLD 并保持使能。屏幕可直接操作；网页点 **连接控制** 可接管本地跟踪／回零／保持状态，不需要先失能；回零过程中仍禁止点框和手动移动。
5. 用几度的小动作验证手动方向和画面旋转，再点击目标。DISARM 和持续视觉／反馈异常可中止初始化；初始化读反馈过程中收到 DISARM 也不会被后续自动回零请求覆盖。中止或故障后不会自动反复使能；排查后 RECHECK → ARM 保持当前位置，再按需 HOME 回零。默认已认可驱动零点，无需每次 ZERO OK；若设 `mechanical_zero_confirmed=False`，则保留人工确认步骤。ZERO OK 不会标定新零点。默认增益与相机视场角仍需实测核对。
6. 屏幕右侧是 ARM、DISARM、ZERO OK、RECHECK、C、HOME 按钮，下方圆形区是手动摇杆。摄像头图像在左侧，黑边不接收目标选择。
7. 网页中点击视频里的框选目标；方向键控制手动移动，空格失能，C 执行两步操作。网页按钮会显示下一次 C 是“清除目标”还是“回原点”。
8. 一个时间只允许一个控制源。网页占用时屏幕普通操作会被拒绝；屏幕 DISARM 随时可停止并撤销网页会话。网页失焦／切后台／离开页面时发送交接请求：清空手动输入、撤销旧网页会话，由相机继续当前目标跟踪／回零或保持。旧会话排队中的按键不再生效，浏览器后台计时器暂停不会终止已交接的本地控制。返回窗口自动接回；另一网页正在控制时不抢占。页面输入框和 Ctrl／Alt／Meta 组合键不触发方向键或 C 快捷操作。

网页心跳超过 0.6 秒也会撤销旧会话、松开手动输入并交回相机，不再直接失能；旧会话不能继续发移动指令。DISARM／空格仍明确请求失能。网页 DISARM 在未连接时也可停止没有其他网页占用的本地控制；相机自主运行不依赖该页面继续打开。

网页需要电脑与相机网络互通，使用相机当前 IP，不是电脑 localhost。端口默认 8080，仅供可信局域网测试；没有账户登录或 HTTPS，不要做公网端口映射。

## 延迟与保护

### 限位外初始化、使能与向内恢复

- 工作限位不阻止读取、重新检查或 ARM 当前姿态；有真实反馈才使能。正常手动／跟踪位置指令限于工作范围。超限时单独启用向内恢复规则，不把限位边界当作使能目标。
- 自动初始化或已使能后明确点击 HOME，先使用当前实测姿态再向机械零点移动。普通 ARM 不回零；超限时允许摇杆小步向范围内移动、松手保持、向外推保持不动，目标选择仍需进入正常范围。
- 回零位置规划仍朝 0°推进，每次目标离实测位置 yaw 不超过 8°、pitch 不超过 6°，不主动向远离零点的方向发新目标。反馈在起始角与 0°路径外的 2°以内不立即报故障，用于起步惯性、耦合和小幅过零偏移；2～5°先暂停新位置帧，300ms 内恢复则继续，持续偏离才失能；超过 5°大幅偏离立即请求失能。正常工作指令限位未扩大。
- HOME 路径许可和超限手动向内许可分别检查。超限手动每轴仍限 3°反馈前置距离，不能一步跳到边界、不能新发远离正常范围的目标；原本位于正常范围的轴继续受正常限位约束。进入正常范围后恢复普通指令检查，没有改大 `CONFIG["limits"]`。
- 使用带符号机械角和相邻小步处理 0/360、±180 的表示边界；不恢复掉电前圈数或电缆绕圈历史，也不能从单圈角推断实体路径无障碍。
- 卡阻、反向或偏离回零路径、跳变、反馈异常、45 秒超时仍会锁定并尝试双轴失能。没有把异常检查一起关闭。

默认自动启动回零采用驱动已有机械零点，不会发送 `0x0A`、`0x08`、`0x09`，不把开机姿态当作新零点。若不需要运行脚本时自动运动，可将 `startup_auto_home=False`，之后用 ARM 保持、HOME 回零。修改本应用配置以 `src/config.py` 或生成文件中的应用 `CONFIG.update(...)` 为准。

### 提速和轻量预测

v6 将摇杆从 v5 的 **480/360 减半到 240/180°/s**，相应驱动速度从 80/60 降到 40/30 RPM、位置前置距离从 24/18 降到 12/9°。HOME **108/90°/s**、跟踪 **150/120°/s** 保持。`tracking_speed_multiplier=5` 在纠偏输出处放大普通误差响应，`step_cap=(15,12)` 保持；丢失预测 COAST 仍为 4/3°/s，切入时立即限制旧速度，不继承高速摇杆或跟踪轨迹。

软件加速度按模式分别限幅，驱动 RPM 也随模式设置，而不是让回零一直沿用手动档。手动加速度上限降为 900/750°/s²；跟踪和 HOME 的加速度配置保持不变。`motor_acceleration=10` 不变，不修改 PID、不保存 Flash。配置速度不等于实测速率：角度行程、加减速距离、UART 查询耗时、控制周期和负载可能使目标上限无法达到。

手动控制使用加速度变化限制（`manual_jerk_deg_s3=(6000,5000)`、`manual_response_s=.10`）处理起步和换向，减少起步冲击；手动和跟踪接近工作限位时根据剩余距离提前降低速度。各模式使用表中的有界前置距离，最终 UART 写入再次检查对应门限、角度限位和 HOME 向零方向；超限手动仍限 3°。仅触及前置距离时不反复清零规划速度，防止电机追赶时一顿一顿。松手、DISARM、短暂反馈异常和硬限位处的立即保持／停止优先于平滑。恢复通信时清空旧加速度，重新从实际姿态起步。

机械反馈可信范围同时参考已成功发出的逐轴位置目标，避免提高驱动 RPM 后，把静止时的异常编码器跳变误判为合法高速运动；写完第一轴便记录其目标意图，第二轴写入期间的反馈刷新也能识别该轴正常移动。v6 在已有目标走廊的前提下，额外计入最多一个位置指令周期（默认 40ms）的采样相位差，避免把合法目标更新集中出现在一次反馈中误判为跳变。仍同时受目标走廊限制，不接受静止时无指令的 20°突跳；被拒绝样本不更新可信时间戳，连续失败 500ms 仍失能。

同向手动输入、速度方向一致时，小幅反馈回摆造成的前置距离裁剪不再撤回已发目标，而是暂不重发、等待真实反馈追上；轻微过冲时也不新发位于实际姿态后方的目标。手动阻尼补偿最多把输入降低到零，不允许反向推动或移动零输入轴。明确反向推杆仍通过减速过零后换向；停滞／反向观察没有关闭。

HOME 接近原点仍减速并检查到位，完成后保持使能。指令保留 0.1°量化去重和每轴约 25Hz 限制，没有增大工作角度范围。网页同时显示摇杆、跟踪和 HOME 三组上限；`/api/state` 给出加速度上限和手动规划加速度，反馈日志也包含规划速度／加速度，便于区分设定值与实际响应。

`ema=(.28,.32)` 按实际帧间隔缩放，`step_cap=(3,2.4)` 按 10Hz 参考频率换算成速度。推理目标从上一版 15Hz 提到 30Hz，预览绘图／JPEG 目标单独限制为 8Hz，优先提交跟踪控制。板上实际推理帧率、速度与振荡情况仍需实测，不能由这些配置值推出。

中心死区缩小至画面宽度的 1.8%、高度的 2%。近中心使用较低反馈增益、远离中心逐步提高增益；越过中心时清掉旧方向滤波，减少推过头后继续往原方向运动。

### 指令／反馈误差自调与 Codex 读取

每次有新鲜双轴机械反馈时，对比**已经发出的目标角度与实际角度**，估计运动速度和误差趋势。相机内的 `ResponseTuner` 实时执行有界调整，不依赖云端 Codex 或网页持续在线：

- 已有实际进展但仍落后：逐步增加软件响应倍率和有限速度补偿。
- 已超过指令位置或速度过快：降低倍率和软件加速度，加强阻尼。
- 没有实际进展：不增加推力式响应，持续无进展交给卡阻保护。
- 失能、反馈缺失期间不调参；靠近正常限位不增加响应；丢失预测 COAST 保持原 4/3°/s 请求上限，不被自调放大。

默认响应倍率 0.8～1.15，倍率变化率最多 0.3/s；额外速度补偿最多每轴 3°/s。最终仍受各模式的速度、加速度、目标前置距离与工作限位约束。软件加速度范围见上表，可用 `adaptive_response=False` 作固定响应对比。

**这不是电流／力矩闭环。** 当前协议提供位置、速度、加速度等反馈，没有实时电流／力矩反馈；没有改动驱动 PID，也不自动写保存命令。驱动 `0x07` 为 T 型轨迹加速度参数，当前单圈直通模式的平滑主要通过软件位置流完成，不能把它称为可测量的“力度”。

网页显示指令−反馈误差、软件加速度、响应倍率，并可下载日志。只读接口：`http://相机IP:8080/api/telemetry`，保存最近最多 600 条、约 10Hz 数据，包括时间、阶段、使能、实际角、指令角、请求速度、反馈年龄、误差和调节状态。也可在电脑运行：

```powershell
python -B MaixCam/apps/yolo_click_tracker/tools/read_feedback.py --url http://192.168.100.210:8080
```

### 机械反馈短时异常宽限

默认 `feedback_loss_grace_s=.5`：每次先实际查询串口。某轴查询失败、校验失败或角度不可信后，才从该次查询开始计时；保留最后可信角度的**原时间戳**，暂停新位置帧并重读，保持使能。任一轴连续查询失败约 500ms 才锁定故障并请求双轴失能；成功回复重置该轴计时，另一轴回复不能掩盖它的失联。NPU/Python 调度使数据变老时，先刷新并读取已排队的有效回复。被拒绝的角度跳变不会仅因等待时间变长就被当成可信新零点。实际动作时刻受查询等待和调度影响，不是硬实时保证。

`feedback_loss_grace_s` 允许范围 0.05～1 秒；每包等待 `feedback_timeout`（默认 40ms）必须小于等于该值的一半。`reference_max_age_s=.25` 仅触发运动前刷新，缓存位置不作为新鲜反馈发运动指令。启动／重新检查仍需真实反馈，不以假零点使能。正常反馈边界容差放宽为 0.8°，超过后也先复核 300ms；偏离正常限位超过 3°仍立即请求失能。初始超限轴另用向内恢复走廊，新目标只可保持或向内移动。UART 写失败与显式 DISARM 不等待宽限。

### 内置模型与推理提速

本程序原本就使用 MaixCAM2 的 **内置 YOLO11n NPU 模型**，不是电脑 `.pt` 推理。本次针对流水线优化：

- `dual_buff=True` 让图像准备与 NPU 运算交叠。结果属于上一次提交的图像，程序保留那一帧图像、读帧时间和机械姿态，始终将检测框画在对应图像上，网页帧 ID、点击与预测也使用同一帧。第一次预热不作为有效检测；预热和相机初始化完成后才启动电机线程。
- 默认 `camera_rotate=True`，相机支持时用水平镜像加垂直翻转完成 180°倒装处理，减少每帧 RGB 拷贝和 OpenCV 旋转。若接口不支持，会恢复原相机方向再使用软件旋转；若恢复失败，则阻止电机启动。启动日志会说明使用哪条路径。
- 网页和屏幕显示实际 YOLO 结果帧率与“读帧至结果”的耗时；网页状态另有 `detect_api_ms`。帧率是最近最多 30 个结果的测量值；耗时以软件读帧时刻计算，包含双缓冲等待，不等于传感器曝光至电机响应的全链路延迟。
- 模型仍通过 `nn.YOLO11` 加载 `/root/models/yolo11n.mud`。若设备已有官方 YOLOv8n，可将 `model_kind="YOLOv8"`、`model_path="/root/models/yolov8n.mud"` 作对比；这里不声称它一定更快。较小输入尺寸需要对应的 MaixCAM2 `.mud` + `.axmodel`，单独缩小相机尺寸不能减少固定输入模型的 NPU 计算量。

若板上版本双缓冲兼容性或内存有问题，可设 `dual_buff=False` 对比；程序会切换为同帧结果对应关系。相机请求帧率可设为 30 或 60。`camera_rotate=False` 可强制使用原来的软件旋转路径，`rotate_180=False` 则完全关闭本程序的倒装旋转。

接口依据：[Sipeed YOLO 文档](https://wiki.sipeed.com/maixpy/doc/zh/vision/yolov5.html)、[双缓冲的上一帧语义](https://wiki.sipeed.com/maixpy/doc/zh/vision/dual_buff.html)、[相机 hmirror/vflip API](https://wiki.sipeed.com/maixpy/api/maix/camera.html)。尚未在本次会话中连接开发板测试，不能据配置声称达到 30fps。

预测参数均在应用的 `CONFIG.update(...)` 中：

| 参数 | 默认值／作用 |
| --- | --- |
| `prediction_enabled` | True；改为 False 可对比关闭预测的效果 |
| `prediction_min_samples` | 同 ID 至少 3 次有效观测；低置信、过长间隔或异常跳变重置估计 |
| `prediction_lead_s` | 提前 0.12 秒，另补偿实际推理延迟（最多再计 0.12 秒） |
| `prediction_max_shift` | 每轴预测偏移最多图像宽／高的 6% |
| `prediction_feedforward` | 估计目标速度的 0.35 倍前馈，最终仍受跟踪速度限制 |
| `prediction_coast_s` | 丢失后最多 0.15 秒低速延续，随后停止；不延长 2 秒丢失时限 |
| `prediction_coast_rate` | 丢失预测 yaw ≤4°/s、pitch ≤3°/s，并逐渐降到零 |
| `pose_max_age_s` | 机械反馈超过 0.2 秒时不用于运动预测 |

图像中的青色 `PRED` 圆圈是预测瞄准位置；黄色框仍对应真实检测。预测以默认视场角和输入方向作近似旋转补偿，方向／视场角需与实机一致；它不会生成新的检测框或跨 ID 认人。手动移动、清除目标、换选目标、DISARM 或故障均清空预测历史。

### 疑似卡阻自动失能

`VisualMotorService` 为本应用启用加强的 `TrackingMotionGuard`，在预位回零、手动和跟踪时都检查目标与实测角度：

- 误差达到 **2°** 后开始观察，先留 **0.6 秒**加速／反馈宽限。
- 同方向误差持续，合计约 **1.8 秒**（0.6 秒宽限 + 1.2 秒观察）朝目标进展不足 **0.2°**，判定疑似卡阻。
- 宽限后反向位移达到 **2°**，先提示观察，持续 **0.4 秒**才触发反向运动故障，单次轻微反弹不直接失能。
- 另检查持续同方向运动请求是否有真实进展，避免反复短丢包擦掉卡阻观察窗口；等待反馈的时间暂停计时，正常限位／原点保持不会误算为卡住。
- 触发 `SUSPECTED_BLOCK` 后记录实测与目标角度，锁定 FAULT 并尝试分别向两轴发送失能命令，清空预位／回零请求；不自动重新使能。
- 排查并支撑负载后，点 RECHECK，通过后手动 ARM，再按需 HOME。默认继续使用已保存零点，不重新标定。成功重新检查才清除上次卡阻诊断记录。

这是位置反馈启发式判断，协议没有公开实时力矩／电流反馈；小于门限的接触、短时或仍能移动的卡阻不保证被检测。失能命令也不是硬件切电，失联时可能无法送达。阈值是待实机核对的起始值，不能用电脑模型证明真实碰撞保护能力。

- 网页每张 JPEG 都带实际图像帧 ID。点击按当时显示帧的框映射，再核对该 ID 仍在当前检测中；过期画面或已消失目标会拒绝，避免把新出现的邻近目标当成旧目标。
- 帧历史有界（默认 12 帧），目标数有界（64 个）。两类相同 ByteTrack ID 使用不同类别键，丢失／预测轨迹不当成当前检测。
- 相机／推理数据超过 0.45 秒先提交零手动输入、暂停跟踪运动并保持使能；超过 `vision_disable_age_s=2` 秒持续无有效画面才请求失能。只有应用主循环喂电机心跳；其输入超过 0.5 秒未更新，驱动先暂停新位置帧，超过 1.2 秒才硬保护失能。恢复时从实测姿态起步，不执行积压运动。
- 网页控制连接 0.6 秒超时后交回相机自主控制；机械反馈宽限与网页心跳分开计时。软件失能不是切断电源，也没有固件已失能 ACK。
- 串口反馈、跳变、工作限位、运动方向与停滞检查继续有效，超限状态仅允许保持或小步向内恢复。故障后排查并点 RECHECK，再手动 ARM、按需 HOME。失能时俯仰轴可能下落，先支撑负载。
