# 声音粗定位 → F32C 转向 → YOLO 精确跟踪

2026-10-03。运行平台：**MaixCAM2 + 固定底座 MA-USB8/MicArray + F32C 双轴云台**。
在 MaixVision 打开 **main.py** 即可运行；这是生成好的独立单文件，无需上传旁边的 Python 模块。
默认 `motor_enabled=False`，只打开声音 UART、相机、屏幕；电机角度是明确标记为 **SIM** 的模拟值，不打开电机串口。
模型文件仍需在板上存在。当前仅完成 PC 合成与假串口验证，未部署、未驱动实物。

已按“电机控制模块”的最新缓存与 `gimbal-zero-worktree/gimbal_demo/3v` 固定机械零点源码更新。真实电机模式启动后保持失能并持续读取角度，需点击 **ARM** 才启动寻向／跟踪。支持独立 `calibrate_zero.py` 设置机械零点并发送保存；新增位置停滞和反向运动保护。

## 已接入的流程

1. `WAIT_SOUND`：使用现有 16×16 热图主连通区域算法，拒绝低信号、多声源歧义、过期数据及标定覆盖外方向。连续新帧方向稳定至少 0.35 秒后触发。
2. `SLEW`：把**固定底座坐标系**中的标定方向作为绝对云台目标角；不叠加当前 yaw。按速率限制转动，必须读取实际电机反馈，到位 ±2° 并持续 0.35 秒才进入下一步；15 秒未到位锁定故障。
3. `SEARCH`：在声音方位附近小幅水平扫视，6 秒内完成左右一轮；幅度受 12° 上限和 4°/秒速度共同约束，默认实际约 ±3.8°。中心附近的同一个视觉 ID 连续出现 3 次后自动选中；两个候选距中心近似时不自动抢选，可以点框。
4. `TRACK`：只跟踪选中 ID；声音不会覆盖视觉锁定。画面中心误差经角度换算、EMA 平滑、死区及单步限幅后调整云台。
5. `LOST`：目标暂时消失就保持当前位置，最多等待同 ID 2 秒；超时释放锁定并等待新声音。不突然回机械零点。
6. `FAULT`：串口失联、控制心跳过期、参考不一致、越界、持续反向运动或停滞等电机故障停止控制并尝试两轴失能，保留串口并继续尝试读取反馈；恢复数据后仍锁定故障，需修复后重启。相机／推理过旧、转向超时等应用异常则退出并释放资源。

屏幕顶端 **STOP** 停止并退出，**CLEAR** 释放目标、等待新声音；**ARM** 请求使能并保持实测当前位置，然后等待新声音；**DISARM** 请求失能并继续读取角度。使能后点击检测框可手动选择对象。控制台每秒输出 `SOUND_YOLO` JSON，含状态、声音向量、质量、累计控制参考、机械角、反馈角、目标角和推理帧率。`armed` 代表程序已发送使能请求，不是固件使能状态回读。`STEP` 日志标出初始化阶段。

自动选择表示“声音方向附近最靠近光轴的视觉对象”，不是声纹识别，也不能证明该对象正在发声；人群重叠、反射和声源遮挡仍需人工选择。

## 与 1101 mainweb.py 的对应关系

| 原逻辑 | 本系统 |
|---|---|
| YOLO、conf=0.5、IoU=0.5、多类别检测 | 保留；默认不限定为 person，可配置 `class_ids=[0]` |
| Ultralytics ByteTrack、持久 ID | 使用 MaixPy 原生 ByteTracker；按类别隔离，键为 `(class_id, track_id)`，避免跨类别 ID 冲突 |
| 鼠标点击选 ID、画框和轨迹 | 触屏点击选 ID、画框、轨迹和指向光轴的误差线 |
| 丢失 2 秒 | 保留壁钟超时；lost/predicted track 不作为新检测 |
| 死区、EMA、单帧转角限制 | 保留思路；死区按分辨率归一化，反馈当前位置加角度纠偏，适配 F32C yaw/pitch |
| 手动选目标 | 保留，并新增声音转向后的连续确认自动选目标 |

默认沿用现有 MaixCAM2 的 `/root/models/yolo11n.mud`。**识别／锁定流程相同不等于模型权重相同**：原项目是 `yolov8n.pt`，若要使用相同训练权重，应准备对应 MaixCAM2 转换后的 `.mud + .axmodel`，将 `model_kind="YOLOv8"` 和路径一并修改。MaixCAM2 不直接加载 `.pt`。Maix 原生 ByteTrack 与 Ultralytics 的 ID 和数值结果不保证逐帧一致。

原项目固定高度 5m 的地面测速没有移植：此处没有已知目标距离／地面几何，不能把像素移动编成 m/s。原 STS3215 的 90° 中位角和 PITCH_ROLL 控制也不适用于 F32C 双轴 yaw/pitch。

## 接线与资源

| 模块 | 默认资源 | 连接 |
|---|---|---|
| MA-USB8 声音热图 | UART1，2,000,000 bps | MA-USB8 TX0 → A31/RX；GND 共地；A30/TX → RX0 可选，本程序不发送板控命令 |
| F32C 双轴总线 | UART3，115200 bps，ID 1/2 | B2/TX → 电机 RX，B3/RX ← 电机 TX，共地；按现有双轴总线方案接线 |
| 保留给其他模块 | UART2、UART4 | 不占现有 Thermal160 UART2；避开 MaixVision 通信 UART4 |

默认串口选择依据已有接入资料和板级引脚图。UART3 启动前检查实际 pinmux 是否提供 UART3_TX/RX；不能通过检查就停止，勿直接把它改成 UART4。实板引脚、电平与总线接法仍须核对。
信号为 3.3V TTL，F32C 独立供电；MA-USB8 使用自己的 USB-C 供电，不把板间 3V3/5V 相连。不要把电机电源接到 MaixCAM2 IO。

## 首次上板

1. 保持电机关闭，先确认已有 MicArray 独立程序能稳定收到二进制热图；本程序复用相同协议。
2. 打开 `main.py`，修改顶部模型路径（若不同）。首次按默认 `motor_enabled=False` 运行，检查图像、检测框、ID、触控、声音向量。未做声音标定时，保持 `WAIT_SOUND` 是正常现象；可手动点框检验视觉链路。
3. 先设置并实测两轴固定机械零点，再按下节取得声音标定。填写电机 `motor_ids`、`motor_signs` 和机械安全 `limits`。默认 `motor_reference="mechanical"` 自动读取固定机械零点参考；不需要手工填写上电累计零位。逻辑 0° 必须是与声音标定一致的底座参考方向。
4. 摄像头 `camera_fov` 是当前项目使用的起始参数，需用实际视场校准；`pixel_sign` 必须通过小角度测试确认“画面偏右／偏下”对应的纠偏方向。
5. 确认标定后设置 `sound_calibrated=True`、`motor_calibrated=True`，最后设置 `motor_enabled=True`。连接后显示 **DISARMED** 并持续反馈，不自动运动；检查实际机械角，点击 **ARM** 后才开始寻向。首次缩窄 `limits`、低速度、单目标测试。默认 pitch 相对固定垂直零位 ±100°，程序禁止设置超过此范围。
6. 实测声音左右转向、反馈到位、视觉锁定、遮挡恢复、连续丢失、ARM/DISARM/CLEAR/STOP 和断流。达到这些验收条件后才算板上联调成功。

可直接编辑 `main.py` 顶部 CONFIG；需要保留可维护源码时同步改 `src/config.py`。重新构建会覆盖 main.py，务必先保存板上配置修改。

## 固定机械零点及独立标定

沿用最新 v3 方案：读取累计角 `T` 和机械单圈角 `M`，将机械角转为带符号 `m=((M+180) mod 360)-180`；此上电会话参考为 `Z=T-m`。逻辑角 `q=(T-Z)×motor_sign`，下发累计目标 `T_target=Z+q/motor_sign`。

例如 Y 在真实零位 +25° 时重新上电、累计角 T=0，参考 Z=-25°；系统仍显示 +25°，目标 0°对应累计 -25°。启动不会自动归零，也不会发送 `0x09` 清累计。连接前请支撑俯仰负载；读取 `累计→机械→累计` 时变化超过 0.2°就拒绝建立参考。运行中机械／累计参考偏差超过 1°就锁定故障；顺序采样误差采用前后累计角中点估算，仍需根据实板速度验证。

若已用最新 PC v3 GUI 设置并确认两轴机械零点，直接复用，无需重复标定。若需要在 MaixCAM2 上标定：

1. 停止跟踪程序和其他电机控制程序，支撑负载，人工将所选轴放到真实零位并保持静止。
2. 在 MaixVision 打开独立 **calibrate_zero.py**，核对顶部 UART、ID 配置；搜索 `ZERO_AXIS`，选择 `"X"` 或 `"Y"`。
3. 确认真实零位后，将 `CONFIRM_PHYSICAL_ZERO=True`，再运行。默认 False 会在打开 UART 前退出。
4. 程序先两轴失能，检查三次速度为 0 RPM 且累计角变化≤0.2°，发送所选轴 `0x0A`，检查三次机械零点误差≤0.5°且轴未移动，再发送 `0x08` 保存。不发送位置、使能和累计清零命令；失败不发送保存。
5. 输出 `ZERO_SAVE_SENT` 仅表示回读实时零点并发送保存。断电重启，在相同物理姿态检查机械角接近 0°后才确认掉电保存；保存命令没有文档化 ACK。

改变机械零点、方向符号或阵列安装后，需要重新检查／采集声音标定。默认 `mechanical` 模式限制两轴在唯一带符号单圈区间内；当前跟踪器不恢复 X 历史圈数。电机单独重新上电后应重启连接，整圈变化等特殊情况下参考一致性检查可能无法发现重置。

`motor_reference="raw"` 仅用于模拟／旧接口资料，不能启用真实跟踪电机；真实运行必须使用机械参考，避免绕过零点丢失保护。

## 零点丢失自动失能

零点参考不可用、被意外改写、非有限数值、机械／累计反馈不一致、关键反馈读取失败或参考数据超过 `reference_max_age_s=0.5` 秒，都会进入锁定故障 `ZERO_REFERENCE_LOST`。检测时间受串口响应和线程调度影响；使能期间反馈查询失败不再重复等待重试，首次查询超时就进入失能处理。

累计角连续性检查使用原始多圈角，不做 360°取模。相邻累计采样的变化超过 `motor_rpm×6×时间间隔 + reference_jump_slack_deg`（默认宽限 2°）会失能，捕获整圈跳变、累计寄存器重置等异常。正常机械单圈 359°/0°环绕配合连续累计角可通过检查。

故障发生后清空目标邮箱、取消使能请求，尝试两轴 `0x05`，随后追加两轮失能请求；每个轴独立尝试，单轴写失败不会跳过另一轴。每个位置帧与使能帧在写 UART 前再次检查参考和数据年龄，失效后不能发送运动帧。反馈恢复只作为诊断读取，不恢复参考、不重新使能；须停止程序，检查真实零位与掉电保存，再重新连接。

固件未公开“Flash 零点已丢失”标志，因此无法识别所有保存丢失情况，尤其在重新连接前零点已改变但角度关系自洽时。软件失能也无法保证在串口物理断线时送达；本功能不能保证阻止所有无限运动事故，独立限位和硬件切电仍是最终保护。

## 运动异常保护

`motion_guard=True` 时，在已发位置目标与实测角度相差至少 3°的情况下监测运动进展：前 0.8 秒留给 T 型加速和通信延迟；随后若相对预期方向反向超过 1.5°，或总计 2.3 秒内正向进展不足 0.5°，锁定故障并请求两轴失能。目标反向或已进入误差门限会重建检测窗口。实际角度超出配置限位、参考不一致和反馈丢失也会停止。

这些是保守起始阈值，须按实际负载、速度和通信时间调试；3°门限以内的接触或能够继续移动的碰撞可能检测不到。位置停滞不是测得力度，保护不等于真正切断电源。硬件切电仍需要外部电源开关／独立监控。

## 固定底座的声音标定

热图 `vector_xy` 是二维归一化图像坐标，不是物理 DOA；`image_bearing_deg` 也不能直接作为 yaw。这里使用实测查表、近邻加权和覆盖半径，不假设热图与角度线性。

将固定底座的朝前方向定义为 yaw=0。保持阵列安装、旋转/镜像参数不变，把单个声源放到已知 yaw/pitch 方向；每个方向记录至少 5 次稳定 `vector_xy`，覆盖实际需要的范围。若只需水平粗定位，可所有 pitch 填同一个搜索高度，垂直方向交给 YOLO。

建立 UTF-8 CSV，列名为 `vx,vy,yaw_deg,pitch_deg`；至少 3 个不同方向，每个方向 ≥5 行。角度应来自底座参照／量角器或确认过的电机实际位置。不要把 SIM 角度拿来作标定真值。

```powershell
python -B maixcam2_sound_yolo_gimbal/calibration_table.py measured_sound.csv
```

脚本输出 `sound_samples`，每行 `[vx,vy,yaw,pitch]`；复制到配置。它会拒绝非数值、明显不稳定、不同角度却热图重合的样本。随后用未参与标定的中间方向测试，确认转向落在相机视场内，再设 `sound_calibrated=True`。代码只允许在最近样本距离 `sound_radius=0.18` 内插值，超过范围就等待，不盲目外推；覆盖不足应补测样本，不宜直接增大半径。

若存在跨 ±180° 的方向，先转为云台连续且安全的多圈逻辑角区间；当前默认 yaw ±150°，不支持随意跨后方或无限旋转。不同距离、混响、声音频率会影响热图位置，实际覆盖与精度需测量。

## 本机验证与维护

```powershell
python -B maixcam2_sound_yolo_gimbal/build.py
python -B -m unittest discover -s maixcam2_sound_yolo_gimbal/tests -v
python -B maixcam2_sound_yolo_gimbal/simulate.py
```

这些命令不导入 MaixPy、不连接硬件；仿真脚本只用标记为 synthetic 的输入演示完整状态变化。`src/` 为维护源码；`vendor/` 为已有声学算法与协议的固定快照；`source_hashes.json` 记录构建输入。原声音模块、电机 demo、1101 代码均未修改或上传。

电机使用独立串口线程和仅保留最新目标的邮箱，连接保持失能，手动 ARM 时重新获取两轴反馈、预装当前位置再使能；使能后控制心跳超过 0.8 秒会尝试两轴失能。退出及初始化异常均尝试清理资源。软件线程无法保证在驱动持有 GIL、整个进程／系统冻结、断电或物理断线时发送停机命令；实机必须能独立切断电机电源。失能后俯仰负载也可能受重力下落，应先固定负载验证。
