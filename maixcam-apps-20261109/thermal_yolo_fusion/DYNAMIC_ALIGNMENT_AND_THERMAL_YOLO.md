# MaixCAM2 + Thermal160：动态对齐与热像 YOLO 路线

状态：设计与接口研究；不是已上板实现。先解决当前主程序首帧停住、热像 `NO THERMAL` 的问题，再用同时间戳采集的双光帧验证任何动态算法。现有可运行入口仍为 [main.py](main.py)。

## 当前应用已做到什么

- 每个距离档位（0.5、1、2、3、5m）保存一张 **热像原始像素 → RGB 相机输入像素** 的平面单应矩阵，DIST 手动选择。广角与窄视场通过热像有效覆盖区域处理。
- RGB YOLO 框映射到同一画布，并使用该变换所覆盖的**热像原始像素**估算框内最高/平均温度；失效或时间错配显示 `T:--`。
- 热像每收到新帧才更新伪彩及投影，可见光可在两张热像之间更新。画在热像层上的 RGB YOLO 框仍来自 RGB 模型，并不表示模型识别了热像。
- 机身上量得的右、下各约 5cm 是粗略安装信息，不等于精确光心基线。当前未测两镜头内参、畸变或刚体外参，也没有实际深度。

## 动态几何对齐的三个层次

### 1. 一个主要工作平面在前后移动：自动选距离

先把当前多档 CAL 做实机标定，覆盖实际工作距离。在场景基本处于同一平面时，用**独立实测距离**自动选择最近档；在相邻距离之间，可对每个热像像素的两个已校准投影坐标做受控插值，并用留出的标记实测误差。不要直接线性混合单应矩阵元素并声称是精确三维投影。对距离加入滤波、切换滞回、可信范围和 `distance_age`，距离失效则保留上一次可信档位并显示 `DIST UNKNOWN`，停止宣称精确测温位置。该层不能处理画面里同时有近人和远墙的情况。

若只想要少量目标的测温，一只单点测距器可提供“目标大致距离”，但必须确认测到的是该目标而不是背景；类别或框大小不能单独证明米数。

### 2. 同一帧中多个深度：双目标定 + 深度图

制作 RGB 与热像都能识别的标定板，在多个位置、距离和倾角采同步图。先分别估计两镜头内参/畸变，再解出热像相对 RGB 的旋转 `R` 与平移 `t`。运行时把热像原像素去畸变，用对应深度 `Z` 反投影成热像坐标中的三维点，再由 `R,t` 投到 RGB 图：

```text
X_thermal = Z · K_thermal⁻¹ · undistort(p_thermal)
X_rgb     = R · X_thermal + t
p_rgb     = distort(project(K_rgb · X_rgb))
```

深度值必须在正确的传感器坐标系、时间和目标表面上；若来自第三只 ToF 相机，还要标定 **ToF↔热像/RGB** 外参，处理其视场和盲区。对前景遮挡做深度冲突检查，越界/被挡像素不得硬贴。一个距离对应一张矩阵无法替代逐像素深度。

Sipeed 的 PMOD_TOF100 提供 25×25 / 50×50 / 100×100 深度矩阵，官方标称 0.2～2.5m、70°×60° 视场；热像官方标称 160×120、34°×26°。因此 ToF100 不能覆盖既定 **3m、5m** 档位。它与 Thermal160 都使用 PMOD 形态，三者并用前要核对实际插槽、SPI/UART 引脚复用、电源和安装空间，不能假设直接插上即可共存。[Sipeed PMOD 规格](https://wiki.sipeed.com/hardware/en/maixcam/tof_thermal.html)、[ToF100 API](https://wiki.sipeed.com/maixpy/api/maix/ext_dev/tof100.html)。

### 3. 无新深度硬件：跨模态目标驱动的在线微调

在已有多距离基线之上，找两路画面都可见的**可信锚点**（例如温热圆点、明显的人体轮廓/中心），在热像到达时更新一个小幅残差位移或仿射变换。只允许有足够数量、空间分布、低重投影误差、相近时间戳的匹配参与；使用平滑和最大位移限制，低置信度时冻结原标定，回退到已验证的档位。不同模态的亮度和纹理不一致，普通 RGB 光流/特征点不应直接套在热图上。温度热点也可能来自背景，不能作为目标对应的唯一依据。此方法适合纠正固定装配的轻微漂移或某个目标附近的局部误差，**不能从一对普通 RGB/热像帧可靠恢复任意场景的真实深度**。

标定靶必须在两种成像中都有明确中心，例如既有可见轮廓又有热对比的圆点；普通黑白打印格在热像中未必可见。已有研究用专用跨模态标定靶完成 RGB/热像标定：[PST900 原论文](https://arxiv.org/abs/1909.10980)。相机几何与双目标定的可用接口见 [OpenCV calib3d](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。

## “YOLO 识别热像”分成两种目标

**A. 给热像画面附上 RGB 的类别与温度：**沿用现有 RGB YOLO，在几何对齐有效、目标位于两镜头共同视场、两帧时间接近时，把检测框/掩膜投影到热像并读取热像原像素。这在白天或 RGB 有足够光照时实现成本最低；夜间看不见的 RGB 目标也不会凭此被检测出来。只用大矩形框测温可能把热背景混入；更好的是分割掩膜或框内中央/高置信区域，并报告覆盖热像的像素数及置信度。

**B. 热像自己检测目标：**采集本机 Thermal160 原始灰度/温度映射帧，按目标类别标注热像坐标中的框，使用夜间/白天、远近、不同环境温度的真实样本训练或微调 YOLO。训练与推理采用同一固定预处理：依据该帧 `lo/hi` 恢复近似温度，再在固定温度窗口裁剪、归一化、复制为模型要求的 3 通道；不要用随帧变化的伪彩 LUT 当成未经验证的稳定特征。模块只给 160×120 的 8bit 像素及帧级遥测，插值到 320×240 只是适配模型输入，并没有增加空间细节。小目标和相似温度目标的漏检仍受原始分辨率限制。

RGB 预训练的 `/root/models/yolo11n.mud` 可以作为接口通路实验，但其 COCO 类别性能不能当作热像模型验收。完成热像数据训练后，导出固定输入大小 ONNX，再转换为 MaixCAM2 的 `.mud` + `.axmodel`，校验 `input_type`、通道顺序、均值/scale、标签顺序，并在板上从热像帧构建模型输入 `image.Image` 送入 `nn.YOLO11.detect()`。双 YOLO（RGB + 热像）需要测 NPU 内存和总吞吐，按热像真实帧率触发热像推理；不要把重复显示的热帧反复推理。Sipeed 的 [训练说明](https://en.wiki.sipeed.com/maixpy/doc/en/vision/customize_model_yolo.html)、[MaixCAM2 模型转换](https://wiki.sipeed.com/maixpy/doc/en/ai_model_converter/maixcam2.html)和 [YOLO11 API](https://wiki.sipeed.com/maixpy/api/maix/nn.html)可作接口依据；热像需要领域数据的原因见 [红外目标检测域适配研究](https://arxiv.org/abs/2110.03143)。

## 推荐实施顺序与验收

1. **恢复稳定取流。**在现有 v1.3.1 主程序确认 `V/T/AI` 都非零，尤其 `THERMAL first frame` 和正确温度；屏幕、RTSP 实际在刷新。当前最后一份用户截图还是 `NO THERMAL / V0`，因此后续算法不能被称作已验证。
2. **实测基线。**在 0.5/1/2/3/5m 采多视角、分散点对，估计内参/外参及畸变；另外留出未参与拟合的场景，记录共同视场内热像坐标误差、时间差、目标温度误差。保持现有校准 JSON 可回退。
3. **先实现 A。**现有 RGB YOLO+热温度路径可复用；增加映射有效性/覆盖率标记，确保背景热点不会被误报为目标温度。
4. **实现 B 的独立实验模式。**确定检测类别并收集原始热像样本、训练热像模型、部署单模型验证，再考虑双模型融合。对两模型的结果按类别、位置、时间和校准置信度关联，不能把一个目标在两路重复计数。
5. **按真实距离需求选动态对齐。**如果只有一个近似平面，自动距离档位成本较低；如果目标分布在多个深度，加入合适量程的深度硬件并完成三相机标定，或承认无深度时只做局部近似。报告各距离区间的误差和失效比例，而不只展示好看的叠加图。

实现前尚缺：要识别的类别、典型目标最小尺寸、真实工作距离范围、是否愿意加测距硬件、热像与 RGB 的同步样例以及 v1.3.1 实机复测日志。这些信息决定训练集、输入尺寸和采用单距离还是逐像素深度方案。
