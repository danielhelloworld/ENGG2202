# wide-motion-v42 独立分支

入口：上一级 `main_wide_motion_v42.py`。它是独立单文件，包含原有 YOLO、网页、屏幕与电机服务，加上本分支的控制和丢失处理；运行时不依赖 `overlay.py` 或旧版 `main.py`。模型文件仍需在板上原路径存在。

先读 [原因分析](ANALYSIS.md)。本次没有修改原 `main.py`、`src/` 或旧版本：116 个既有源码/文档/记录的 SHA-256 已校验。

## 改动

- 小误差保留 v41 的速度控制和平滑，大误差连续增加追赶能力。高速追赶余量由 30/24°/s 逐渐增加到 100/70°/s，始终服从总转速、制动曲线及机械保护。
- 大误差参考采用“预测位置 + 观测残差平滑”，而非完全旁路平滑；大幅真实运动/方向变化能快速通过，小幅检测噪声被减弱。
- 目标暂时出画时，仅在历史速度可信时短时减速续跟，最多 0.35s、预测目标位移 yaw 24° / pitch 8°。到达预测位移边界便撤去对应速度前馈。这个位移边界是参考值，不能当作真实惯性制动行程的保证。
- 0.9s 内允许对唯一、同类别、置信度至少 0.65、大小合理、接近预测方位的候选，连续两帧确认后接续新 ID。它没有外观识别，不能证明身份；多人歧义、远处目标、低置信度或过时观测不自动接续。
- 丢失超过 2s：释放锁定并保持当前位置，不自动 HOME。需要重新点选；主动 HOME 和启动自动回零保持原功能。
- 新增 `WIDE_V42` 每秒结构化日志及 `wide_pause_reason` / `wide_pause_counts` / `performance.wide_motion` 状态，保留原来的停速、卡阻和失能保护。

## 运行

1. 停止其他占用相机和 UART3 的程序。
2. MaixVision 打开 **`main_wide_motion_v42.py`**，核对模型路径、接线和零点配置，再运行。**仍沿用 `startup_auto_home=True`，启动会使能并回零。**
3. 先验证小幅跟踪，再连续横移超过 100°，最后验证短时出画。极快移到视场之外时，单目相机不能知道人物的新方位，新版会有界续跟后保持，不作无限盲转。
4. 若仍出现停顿，保存对应的 `WIDE_V42` 日志及 `/api/telemetry`。重点看下表，不要直接放松限位或反馈保护。

| 标记 | 可能说明 |
| --- | --- |
| `IDENTITY_OR_FOV_LOSS` | 目标不在当前输出轨迹里；可能出画、漏检或 ID 变化 |
| `FEEDBACK_PAUSE` | 至少一个轴的角度反馈缺失/被拒绝，已停速等待 |
| `MECHANICAL_LIMIT_PAUSE` | 反馈位置偏离工作或回零路径，需要复核 |
| `CONTROL_HEARTBEAT_PAUSE` | 相机/控制主循环心跳变慢，已停速 |
| `RPM_CEILING` | 速度请求达到配置上限 |
| `COMMAND_ACTUAL_SPEED_GAP` | 指令速度明显高于当前估计实测速度；可能是起步瞬态、负载、驱动限速或调度问题，不等同已确认机械卡阻 |

还应比较实际推理 FPS、取图到控制 p95、UART 循环 p95、`command_rpm` 和 `measured_deg_s`。这些数据才能确定真实硬件的主要瓶颈。

## 维护与验证

维护 `overlay.py`，执行 `python apps/yolo_click_tracker/wide_motion_v42/build.py`。构建器只生成新的单文件和本目录构建记录；旧版源码变动时会拒绝悄悄替换基线。

- 新分支 22 项测试通过，覆盖 150°连续转动、跨 ±180°、短时出画不切换模式、同 ID 恢复、谨慎接续新 ID、保持/主动 HOME、卡阻与反馈停速等。
- 121 项原有电机、保护及本地 HTTP 测试已转到新入口验证通过。总计 143 个不同测试，均为 PC/模型验证。
- 在合成 90°/s、持续 2s 共 180°的案例中，追赶平均误差约从 8.66°降为 6.40°；110°/s、共 220°时约从 12.37°降为 8.42°。12°/s 小幅场景的指标与 v41 一致。
- 极端的 150°/s 瞬时起步模型仍会出画，两个版本都不能恢复目标；新版按有界策略保持，不自动回零。快速目标突然停止时，部分模型仍有 20～31°的过冲，不代表实机测量，也不能保证消除过冲。
- 大误差参考噪声测试改善，但整数 RPM 造成的全链路静止噪声结果不是每种输入下都严格更好。保留真实小幅表现，实机还需复核。

完整假设和包括失败场景在内的指标见 `validation.json`，旧文件清单见 `previous_files_sha256.json`。本次未连接板端、未替用户运行电机，也未保存任何驱动器参数。
