# 一键软件整定与 F32C PI 整定

两个入口都在 MaixCAM2 本地执行。电脑网页用于启动、查看、取消和保存。正常启动仍按应用的启动配置回零，自动整定通过按钮主动启动。

## 软件自动整定

维护源码为 `src/software_autotune.py`，已包含在本目录生成的 `main.py`，版本 `autotune-v15`。

1. 在 MaixVision 运行本目录 `main.py`，等待回零完成。
2. 通过网页选择一个静止、清晰且持续可见的目标，等待目标进入中心 4° 范围并松开摇杆。两轴位置需距工作限位至少 6°。
3. 在“软件自动整定”选择 X 或 Y，点击“开始软件整定”。程序依次试验基线、增益 ±15%、EMA ±0.1 和加速度降低 15%。每个候选只改变所选轴的一类参数。
4. 每轮使用约 +4°、回中心、−4°、回中心的视线偏移，每段 1.5 秒。每轮开始前等待视线与机械运动稳定。误差均方根、末段误差和峰值误差组成评分。
5. 候选比较后，重新测量基线并复测候选胜者。基线漂移过大时恢复原参数，复测改善达到 5% 时采用候选，否则保留基线。整定总时限为 120 秒。
6. 点击“保存验证结果”，配置原子写入 `/root/gimbal_autotune/software_profile.json`。下次启动会校验模型、视场角、方向与限位后加载。换相机、支架或负载后重新整定。

板端 API 为 `hub.software_autotune.start(axis)`、`abort(reason)`、`export()` 和 `save()`，axis 0 为水平，1 为俯仰。正常控制入口负责持有 hub 的锁。报告也可以从 `/api/autotune` 下载。

选中的目标必须保持静止。目标丢失、画面过期、反馈异常、实测姿态离开始位置超过 8°，或手动操作都会中止软件整定并恢复原软件参数。网页退出后按现有交接逻辑由相机继续运行。

## F32C PI 自动整定

维护源码为同级 `../motor_joystick/src/pi_autotune.py`，运行入口为同级 `../motor_joystick/main_web.py`。先停止跟踪程序，再启动电机调试程序，保持 UART3 由一个程序控制。

1. 等待回零，连接控制。选择测试轴，填写已经确认可用的 Kp 和 Ki 基线。
2. 松开摇杆，等待当前位置稳定。两轴位置需距工作限位至少 3°。
3. 点击“开始 PI 自动整定”。现有串口工作线程依次写入已知基线和小幅候选值。候选分别对 Kp、Ki 做约 ±15% 的单项改动，整数范围 0～256。
4. 每轮只动选中轴，围绕起始姿态执行 +1°、返回、−1°、返回，每段 1.5 秒。另一轴维持原目标。
5. 程序重复基线、复测候选胜者，再回到测试起点并保持使能。评分和候选验证使用与软件模块相同的流程。
6. 点击“保存验证配置”，将报告保存到 `/root/gimbal_autotune/pi_profile_axis0.json` 或 `pi_profile_axis1.json`。可从“导出本轮 JSON”取得整定报告。保存的是板端配置文件，驱动 PI 写入保持为临时参数。

板端启动 API 为 `service.request_pi_autotune(axis, kp, ki)`，取消 API 为 `service.cancel_pi_autotune()`。请求只写入邮箱，试验、位置指令和 PI 写入由现有 UART 工作线程处理。报告为 `service.pi_autotune.export()`。

“取消并恢复基线”会回到起点、等待静止，再发送已知基线。DISARM、反馈断流或写入失败时，报告标记 `restore_pending`，需要恢复有效反馈后人工确认参数。协议没有文档化的 PI 读回和写入 ACK，因此报告保留的是发送记录和对应的实测响应。已保存 PI 文件供人工核对和下次填写基线使用。

网页后台或心跳超时会将正在运行的 PI 整定交给相机。完成后相机保持测试起点，可重新连接网页接管。DISARM 按钮始终执行失能请求，偏心俯仰负载需要受到支撑。

## 实现与验证范围

公共状态机位于 `../motor_joystick/src/autotune_core.py`。每次整定最多 8 个候选，观测间隔超过 250 ms 或数据非法会终止当前试验。程序按样本时间积分误差，候选列表和报告容量有界。

第一版评分使用图像与编码器，公共观测接口保留可选陀螺仪指标。IMU 实机采样及其评分权重尚待接入。输出是在本次姿态、目标和有限候选集合内经复测比较的参数，其他姿态和实际工作运动仍需检查。

电脑测试覆盖一阶响应模型的候选选择、基线漂移拒绝、取消恢复、失联状态，软件模块的目标丢失与网页交接，以及 F32C 协议模型的单轴运动和保持使能。当前无实机运行实例，尚无真实负载的整定结果。
