## 3. 已核对的资料与串口协议

厂商资料根目录：`E:\WHEELTEC F32C无刷电机无刷云台附送资料`。

重点手册：

- `E:\WHEELTEC F32C无刷电机无刷云台附送资料\【WHEELEC】F32C无刷电机无刷云台电机资料_V1.0_2026.06.09\1.上手手册与视频\F32C无刷电机使用手册-2026-07-21.pdf`
- 同目录的 `F32C二自由度云台使用手册-2026-07-18.pdf`。
- 零点依据：电机手册 §4.1、§4.2.8～4.2.10、§4.2.13、第 6 节；力度/电流反馈与堵转注意事项依据同手册的反馈说明和注意事项。

接线与数据：

- 电机独立供电 8～15 V；电脑使用 3.3 V USB-TTL，不是 RS-232。
- 转换器 TX → 电机 RX，转换器 RX ← 电机 TX；信号地与电源负极共地，断电接线。
- 串口 115200、8N1、无流控。默认 X/yaw=ID 1，Y/pitch=ID 2；实际 ID、COM 口每次重新确认。
- 帧：`7A ID CMD DATA BCC 7B`；BCC 为从帧头到数据末字节的 XOR；多字节大端。
- 多圈角度是 signed int32、单位 0.1°；反馈固定 9 字节，检查 ID、类型、BCC 和帧尾。
- 总线帧至少间隔 1 ms，v3 默认 2 ms，由一个后台线程串行读写。
- 模式 1=多圈 T 型轨迹，2=单圈 T 型，3=多圈直通，4=单圈直通。GUI 使用模式 1；CLI 默认模式 3。

### 零点命令（以下为 ID 2）

| 操作 | 完整帧 | 注意 |
|---|---|---|
| 设置单圈机械零点 | `7A 02 0A 72 7B` | 当前物理姿态设为机械 0°；串口可以直接设置 |
| 保存参数 | `7A 02 08 70 7B` | 保存该电机当前可保存参数，不只零点；没有文档化保存 ACK |
| 读取机械角度 | `7A 02 0E 02 74 7B` | 读取当前相对零点的单圈位置，不是 Flash 内部偏移参数 |
| 读取累计角度 | `7A 02 0E 01 77 7B` | 当前上电会话累计角度 |
| 清累计角度 | `7A 02 09 71 7B` | 临时清累计寄存器，不能代替永久机械零点 |
| 请求失能 | `7A 02 05 7D 7B` | 失能不是切断电源，协议没有已失能状态确认 |

永久零点按 `0x0A → 回读机械角度 → 0x08` 操作。厂家上位机不是唯一入口。Flash 掉电保存必须在实机断电重启后复测，不能用发送成功或软件模型证明。

## 4. 当前代码已实现

- 初版 v3 保留 GUI、实时角度/失能读取、速度、加速度、速度环 PID、状态查询、CLI 和 K230 入口。
- 修复 X GUI 范围不一致、K230 默认 Y 范围超过 ±100°，统一限位异常。
- 反馈超时支持重试、坏帧重同步、原始 `RX=` 诊断；没有双轴有效反馈不自动使能。
- 运行中反馈丢失尝试失能并保留串口，恢复后需要手动使能；不是所有超时都能由软件修复，仍需核对电源、接线和 ID。
- 新 GUI 默认 `mechanical` 固定机械参考，连接时发送双轴失能命令，并保持读取相对角度和单圈机械角度。
- 新增 X/Y 单轴“当前位置设为零点并保存”。要求支撑负载、失能、真实零位和静止；三次速度=0 RPM、累计角度变化≤0.2°；置零后机械误差≤0.5°并检查未移动，再发送保存。
- 标定中途失败会使当前参考失效并阻止使能；回读失败时不发送保存。设置完仍不自动使能。
- 手动使能前预装当前实测保持位置，避免旧目标导致跳转，并同步 GUI 目标控件。
- 目标 Y 超出 ±100°在发位置帧前拒绝；GUI 实测 Y 越界或累计/机械参考不一致时尝试失能。
- CLI 新增 `set-zero --axis Y --confirm`；`probe` 读取累计和机械角度。

**模式差别必须保留在后续讨论中：** GUI 默认固定机械参考；共享驱动、CLI 默认仍是 `software`，CLI 运动需要显式 `--reference mechanical`；独立 `k230_f32c_demo.py` 的零点逻辑尚未升级。不能声称所有入口均已具备固定机械限位。

### 固定机械参考的换算

以度表示：机械角度 `M` → `m=((M+180) mod 360)-180`；同时读取累计角度 `T`；控制零点 `Z=T-m`。

- 下发多圈目标：`T_target=Z+q`；显示反馈：`q_feedback=T_feedback-Z`。
- 例如上电时在机械 +25°、累计 T=0°：Z=-25°，显示 +25°；目标 0°应发累计 -25°。
- 建立参考时需要静止；无需自动移动或发送 `0x09`。
- Y 的 ±100°内带符号单圈位置唯一，正常运动使用多圈命令。单圈最短路径可能穿过背面禁区，不能用于任意 Y 目标之间的运动。
- X 可在当前供电会话多圈运行；断电丢失的历史圈数/电缆绕圈数无法从单圈角度恢复。
- 电机重新上电后必须重新连接。累计与机械角度一致性检查不是所有重启/整圈变化都能检测出来。

## 5. 力度、障碍与停止：已知边界和待做事项

手册公开反馈类型只有：0=速度 RPM、1=累计角度、2=机械角度、3=加速度、4=母线电压（原值×0.01 V）。没有公开实时电流、力矩/力度或过流故障状态接口；不能把母线电压当作力度。

厂家提到内置过流保护，但本对话资料中没有可供软件读取的保护阈值或故障反馈。手册警告高速突然硬堵转可能产生回生过压并损坏驱动。

尚未实现专用“堵转、遇障碍、错误方向”监测。后续可考虑目标与实测角度误差、变化方向、无进展时间，并为 T 型加速/减速和通信延迟留容差；不能把位置误差直接宣称为测得力矩。阈值必须根据真实负载试验确定。

若用户说“自动断电”，要区分：发送 `0x05` 是请求失能；真正切电需要外部电源开关/急停和独立监控。Y 失能可能因重力下落，机械支撑或配重必须纳入方案。本次没有实现硬件切电，也没有测试真实堵转。

实机命令仅供用户选择执行；缓存读取不执行它们，COM5 是占位示例：

```powershell
python gimbal_gui.py
python demo.py --port COM5 probe
python demo.py --port COM5 set-zero --axis Y --confirm
python demo.py --port COM5 --reference mechanical --speed 10 manual --x 0 --y 5
```

核心 API 在 `gimbal_demo/3v/f32c_protocol.py`：`F32CGimbal(..., reference_mode="mechanical")`、`start(enable_motors=False)`、`read_mechanical_angles()`、`read_relative_angles()`、`set_mechanical_zero(y_id)`、`enable_at_current_position()`、`set_relative_angles(x,y)`、`disable()`、`stop()`。设置零点 API 会发送保存命令；不应在每次连接时调用。
