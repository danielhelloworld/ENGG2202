# F32C 双轴控制 GUI

## 启动

在 VS Code 终端进入本目录：

```powershell
python -m pip install -r requirements.txt
python gimbal_gui.py
```

没有连接硬件时，可以先运行模拟模式检查界面：

```powershell
python gimbal_gui.py --demo
```

## 实机操作顺序

1. 固定云台，暂时拆除危险或贵重负载。
2. 断电完成 USB-TTL 与云台接线，确认 3.3V TTL、TX/RX 交叉、信号共地。
3. 支撑云台负载。默认参考模式 `mechanical` 使用电机保存的固定机械零点；首次使用必须按下节标定真实垂直零位。
4. 给电机主回路供电，在 GUI 选择对应 COM 口和 X/Y 电机 ID（默认 1/2）。初次测试建议速度 10～20 RPM、加速度 50～100。
5. 点击“连接并保持失能”。程序发送失能命令，读取双轴总角度与机械角度，设置“多圈位置 T 型轨迹”、速度、加速度；不会自动运动。
6. 确认显示的 Y 相对角度符合实际姿态，再点击“电机使能”。程序保持当前位置；随后用滑块或数值输入改变目标。
7. 点击“电机失能”只关闭电机扭矩，不关闭串口；实时相对角度和单圈机械角度仍会持续更新。再次使能前程序读取当前位置并保持它，参考不变。若 Y 位置超出 ±100°，使能会被拒绝。
8. 点击“断开串口”或关闭窗口时，程序会先失能两台电机再关闭串口。

## 平滑运动与停止震荡

GUI 使用厂家推荐的“多圈位置 T 型轨迹模式”，而不是位置直通模式。速度和加速度可以在连接后修改：

- 速度越高，到达目标越快，但大负载更容易出现超调；
- 加速度决定启动和停止冲量。轨迹不平滑或停止冲击大时，先降低加速度；
- X 轴 GUI 指令范围为 `-360°～+360°`，通过多圈绝对角度协议发送；
- Y 轴仍有相对所选零点 `-100°～+100°` 的驱动硬限制。

## 速度环 PID 调试

厂家资料给出的速度环 PID 范围为 `0～256`，经验范围为 KP `5～50`、KI `5～100`。GUI 不会在连接时自动覆盖电机 PID：

1. 选择 X 或 Y 轴；
2. 从较小的 KP/KI 开始，点击“临时应用”；
3. 每次只小幅增加一个参数并观察到点超调、回摆和高频振动；
4. 效果确认后再使用“应用并掉电保存”。保存操作有二次确认。

负载下到点超调或往回修正过大时，可小幅增加速度环 KP，再视情况增加 KI。参数过大会引起空载高频振动。位置环 PID 按厂家说明通常不需要修改，因此 GUI 只开放速度环。

## 安全层级

Y 轴允许范围固定为相对所选零点 `-100°～+100°`：

1. Y 滑块只显示该范围；
2. 数值输入会拒绝区间外数值；
3. GUI 到后台线程的接口会再次检查；
4. 基础驱动在生成任何位置帧之前进行最终检查。

因此越位命令不会写入串口。X 轴的 `-360°～+360°` 是 GUI 操作范围；F32C 多圈协议本身支持更大的累计角度。

## 设置并保存机械零点

1. 点击“连接并保持失能”，支撑住负载，把 Y 轴手动放到真实垂直零位，等待轴静止。
2. 在“机械零点标定”选择 `Y`，点击“当前位置设为零点并保存”并确认；X 如需标定，可另外操作一次。
3. 后台检查三次累计角度与速度；静止后发送 `0x0A`，回读单圈零点，再发送 `0x08` 保存。不会发送运动、使能或累计角度清零命令。保存也会保存该电机当前其他可保存参数。
4. 成功后自动采用 `mechanical` 参考，仍保持失能。此时被标定轴机械角度应接近 `0°`。
5. 断开串口，支撑住负载，断电再上电。用 `mechanical` 模式重新连接，在同一物理姿态检查零点是否仍接近 `0°`，再在允许范围内手动改变姿态检查角度符号。

厂家手册没有描述保存成功应答，界面只能确认当前零点回读正确及已发送保存命令，掉电保存须实机复测。标定中断后本次连接阻止使能，可重新标定；标定前的姿态不是用软件估计的，必须由人确认真实机械位置。

参考模式在连接前选择：`mechanical` 使用固定零点；`software` 保留旧版行为，把连接姿态当作本次软件零点。`software` 模式本身不会写 Flash，不适合作为固定物理限位基准。

固定参考按 `机械角度 → [-180°,180°)` 换算，再用 `累计角度 - 带符号机械角度` 建立当前上电会话的控制零点。界面显示的“控制零点在累计角度寄存器中的坐标”不一定为 0，这不影响固定机械零点。建立参考时轴需要保持静止。X 断电丢失的圈数不能由单圈角度恢复。

GUI 运行中检测到 Y 实测越界或机械反馈与累计参考不一致，会尝试失能；这是串口软件检查，不是独立限位或硬件断电。电机独立重启后应断开并重新连接，不要沿用旧参考。独立 K230 示例仍沿用旧的软件参考，见 [MECHANICAL_ZERO.md](MECHANICAL_ZERO.md)。

## 连接与反馈超时

串口打开只说明 Windows 能访问该 COM 口。若启动时没有有效反馈，GUI 会保持串口并每秒重试；电机仍需手动使能。首次恢复反馈时按所选模式建立参考。运行中反馈中断会尝试失能并保持串口打开，恢复时保留原参考；没有电机失能应答，实际失能状态无法确认，应检查设备现场。

可先用 `python demo.py --port COM5 probe` 只读探测。`RX=<no bytes received>` 表示目前没有收到任何字节；检查电机独立 8～15 V 供电、USB-TTL 3.3 V 逻辑、TX/RX 交叉、共地和实际电机 ID。若 RX 有字节但无有效帧，检查接线干扰、波特率和 ID 冲突。软件无法修复断线或无电源的电机。
