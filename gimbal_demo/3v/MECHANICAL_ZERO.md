# 固定机械零点：协议、标定与多圈参考

核对日期：2026-10-03。来源：资料包《F32C无刷电机使用手册-2026-07-21》，第 4.1、4.2.8～4.2.10、4.2.13 和第 6 节。厂家上位机不是唯一设置入口，TTL 串口直接支持这些操作。

## 命令差别

| 操作 | ID 2 的完整帧 | 含义 |
|---|---|---|
| 设置单圈机械零点 | `7A 02 0A 72 7B` | 将当前物理姿态设为单圈 0° |
| 保存参数 | `7A 02 08 70 7B` | 保存该电机当前可保存参数，手册要求设置后执行 |
| 读取机械角度 | `7A 02 0E 02 74 7B` | 读取相对已设置零点的当前单圈角度，单位 0.1° |
| 读取累计角度 | `7A 02 0E 01 77 7B` | 当前上电会话的累计角度，单位 0.1° |
| 清累计角度 | `7A 02 09 71 7B` | 临时清累计寄存器；不能替代永久机械零点 |

读取机械角度并不能读取 Flash 内部保存的编码器偏移参数。手册称单圈零点可掉电保存，第 6 节进一步要求点“保存设备参数”；本 demo 按 `0x0A → 回读检查 → 0x08` 执行。协议没有描述保存完成应答。

## GUI

运行 `python gimbal_gui.py`，选择 `mechanical`，点击“连接并保持失能”。支撑负载，把 Y 放到真实垂直零位，选 Y 并点击“当前位置设为零点并保存”。完成后保持失能，断开、断电、重启，再按同一物理姿态检查机械角度接近 0°。完整操作见 [GUI_README.md](GUI_README.md)。

不会自动移到零点；失能时手动摆放并保持静止。程序检查三次速度为 0 RPM、累计角度变化不超过 0.2°，设置后检查机械零点误差不超过 0.5°并且轴未移动。读回失败不会发送保存，当前连接阻止使能，需重新标定。

## CLI 与 API

从本目录运行；以下标定命令会实际改变所选电机参数：

```powershell
python demo.py --port COM5 set-zero --axis Y --confirm
python demo.py --port COM5 probe
python demo.py --port COM5 --reference mechanical --speed 10 manual --x 0 --y 5
```

`set-zero` 发送双轴失能命令，不发送位置、使能和累计清零命令。`--confirm` 表示已经支撑负载并确认静止物理零位。未指定时不会打开串口。使用模拟协议可运行 `python demo.py --dry-run set-zero --axis Y --confirm`。

```python
from f32c_protocol import F32CGimbal

bus = F32CGimbal(serial_port, reference_mode="mechanical")
bus.start(speed_rpm=10, enable_motors=False)  # 不自动运动
print(bus.read_mechanical_angles())         # 单圈角度，失能也可读取
print(bus.read_relative_angles())           # 相对固定机械零点的累计角度
# 支撑负载，人工摆到真实零位；仅在需要重新标定时调用：
bus.set_mechanical_zero(bus.y_id)
# 确认标定与现场位置后，才显式调用 enable_at_current_position / set_relative_angles。
```

## 单圈与多圈如何衔接

机械角度 `M` 转为带符号位置 `m = ((M + 180°) mod 360°) - 180°`，例如 350° 视为 -10°。建立参考时读取累计角度 `T`，取 `Z = T - m`。之后多圈目标 `q` 下发为 `T_target = Z + q`，反馈显示 `T_feedback - Z`。

例如上电时 Y 在固定零点 +25°，累计寄存器 T=0°，则 Z=-25°，GUI 显示 +25°，目标 0° 对应累计目标 -25°。因此不需要先驱动到零位，也不需要发送 `0x09`。连接和使能保持当前姿态；只有用户下发目标才移动。

Y 在 -100°～+100° 内具有唯一带符号单圈位置，后续采用多圈路径，避免单圈“最短路径”经过背面的禁区。实测越界时 GUI 尝试失能。机械与累计反馈差异超过 1°时也会阻止继续操作；这是顺序串口采样，高速移动可能触发保守停止。

X 可以在当前供电会话中多圈运行，但重新上电后单圈传感器不能恢复历史圈数或电缆绕圈数。极端情况下整圈变化或断电发生在特殊位置，单圈一致性检查不能发现累计参考失效；电机重启后必须重新连接。软件限位不能替代独立限位开关、机械保护或硬件急停。

本次仅升级 PC GUI、CLI 及共享驱动的可选参考接口。独立 `k230_f32c_demo.py` 仍使用旧的软件零点；不能把 GUI 已标定解释为 K230 示例自动具备固定机械限位。

## 验证边界

PC 模型测试独立模拟物理位置、上电累计寄存器和 Flash 零点，验证了保存、重新上电、负角度环绕、越界拒绝使能、错误/丢失回读阻止保存，以及失能时 GUI 线程持续反馈。实际设备的 `0x0A` 执行时间、Flash 保存和掉电复测尚未验证。
